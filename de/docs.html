Voraussetzungen

notionkit.css auf dem Dokument laden und class="nk-body" auf <body> setzen. Die Shadow Roots erben Schrift, Farbe und den Scoped Reset von dort; die Elemente bringen kein eigenes visuelles CSS mit. Das Bundle injiziert zusätzlich die Design-Tokens als Cascade Layer (@layer notionkit-defaults): Eine Seite ohne Stylesheet rendert trotzdem, und jedes eigene, unlayered :root { --nk-* } gewinnt.

<html lang="en" data-theme="light">
  <head>
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@jungherz-de/notionkit@1.17.0/notionkit.min.css">
    <script src="https://cdn.jsdelivr.net/npm/@jungherz-de/notionkit-elements@1.17.0/dist/notionkit-elements.min.js"></script>
  </head>
  <body class="nk-body">
    <nk-btn variant="primary">Speichern</nk-btn>
  </body>
</html>

Hosts sind display: contents

Jeder <nk-*>-Host ist display: contents: Er erzeugt keine eigene Box, das innere .nk-*-Element nimmt also genau dort am Eltern-Layout teil, wo es das Klassen-Markup täte – ein Button bleibt inline, eine Sidebar ist direktes Flex-Kind der App, Baumzeile und Kinder-Box sind Geschwister. Das ist der Grund, warum die Pixel-Parität hält. Konsequenz: das Elternelement (oder die Tokens) stylen, nicht den Host; hidden am Host funktioniert weiter; getBoundingClientRect() eines Hosts ist leer.

<!-- ✓ spacing on a wrapper you own -->
<div style="margin-top:16px"><nk-btn variant="primary">Speichern</nk-btn></div>

<!-- ✗ the host has no box; this margin does nothing -->
<nk-btn style="margin-top:16px" variant="primary">Speichern</nk-btn>

Theming & Branding

data-theme="light|dark" auf <html> setzen – nirgends sonst. Ein Observer spiegelt es in jedes Element. Zum Rebranding Tokens auf :root in einem normalen Stylesheet deklarieren: Jedes Element folgt, in beiden Themes.

<style>
  :root { --nk-accent: #16a34a; }
  [data-theme="dark"] { --nk-accent: #4ade80; }
</style>
<script>document.documentElement.dataset.theme = 'dark';</script>

Sprachen

Die Texte, die die Elemente mitbringen – Button-Beschriftungen, Platzhalter, die Namen, die ein Screenreader ansagt –, gibt es auf Englisch und Deutsch. Die Sprache ist die des Elements: sein nächstes lang-Attribut, auch über Shadow Roots hinweg, sonst <html lang>. Ein Attribut am Element gewinnt, für eine Beschriftung mit eigenem Sinn. setStrings() ergänzt oder ersetzt Texte, für alle Sprachen oder eine, und die Elemente auf der Seite übernehmen sie sofort; ein eigenes NkElement liest sie mit this.str(key). Prozente folgen der Sprache, wie Intl sie schreibt – 45 % auf Deutsch.

<html lang="de">  <!-- the elements speak German: Kopieren, Heute, ＋ Neue Seite … -->

<script type="module">
  import { setStrings } from '@jungherz-de/notionkit-elements';
  setStrings({ newPage: '＋ New course' });       // every language
  setStrings({ copy: 'Copier' }, 'fr');           // a language of its own
</script>

<!-- an attribute wins -->
<nk-copy-field value="https://…" copy-label="Link kopieren"></nk-copy-field>

Formulare

Formular-Controls sind form-associated Custom Elements: In einem <form> erscheinen sie in FormData, folgen reset, respektieren required und <fieldset disabled>. Außerhalb eines Formulars funktionieren value und Events weiter, aber nichts wird abgeschickt.

<form id="f">
  <nk-field label="Anzeigename"><nk-input name="name" required></nk-input></nk-field>
  <nk-field label="E-Mail-Benachrichtigungen"><nk-switch name="notify" checked></nk-switch></nk-field>
  <nk-btn type="submit" variant="primary">Speichern</nk-btn>
</form>
<script>
  f.addEventListener('submit', e => { e.preventDefault(); console.log([...new FormData(f)]); });
</script>

Light-DOM-Kinder

Elemente, die ihre Kinder kopieren (nk-select-Optionen, Breadcrumb-Einträge), beobachten sie per MutationObserver – ein Framework, das Kinder austauscht, hält das Element synchron. element.refresh() ist der Notausgang. Der leere String ist ein gültiger Wert.

const sel = document.querySelector('nk-select');
sel.innerHTML = roles.map(r => `<option value="${r.id}">${r.name}</option>`).join('');
// the shadow <select> follows; sel.value is preserved when the option still exists

Icons übergeben

::slotted() trifft nur den zugewiesenen Knoten selbst. Ein Icon als direktes Kind mit Slot-Namen übergeben – nie in einen Container verpackt.

<!-- ✓ the icon is the slotted node -->
<nk-callout><span slot="icon">📌</span>…</nk-callout>

<!-- ✗ wrapped: ::slotted() cannot reach the inner node -->
<nk-callout><span slot="icon"><em>📌</em></span>…</nk-callout>

Overlays

nk-modal, nk-sheet, nk-peek, nk-cmdk, nk-toast und ein schwebendes nk-menu direkt unter <body> platzieren. In einem transformierten oder clippenden Container ist ein fixed Overlay gefangen. Ein Overlay, das über einen URL-Hash aufgeht, braucht eine andere id als den Hash: Der Browser scrollt zum Fragment-Ziel und nimmt dem Overlay den Fokus, den es gerade gesetzt hat.

Editor

NotionKit liefert keinen Editor. nk-block-host ist die optische Hülle; TipTap wird mit dem Rezept unten in ein Light-DOM-.nk-block-host gemountet (die Demo-App nutzt genau diese Datei). <nk-editor>, ein dünner TipTap-Wrapper, folgt in v1.1 als optionaler Import – nie Teil des Core-Bundles.

<div class="nk-block-host" id="editor">
  <p>Server-rendered content becomes the initial document.</p>
</div>

<nk-calendar> Datumsauswahl

Notions Datumsauswahl als ein Element (NotionKit 1.9.0): ein Monat mit Heute und ‹ ›, Tasten, Grenzen und einem Formularwert. Der Wert ist ein Tag (YYYY-MM-DD); mit range ein Zeitraum start/ende, in zwei Klicks in beliebiger Reihenfolge gewählt; mit time ein Tag mit Uhrzeit (YYYY-MM-DDTHH:MM). weeks stellt jeder Reihe die ISO-Kalenderwoche voran („KW“ auf Deutsch), weekend graut die Tage ohne Arbeit, die Property days ergänzt Feiertage (off mit label) und bis zu drei marks je Tag in den neun Farben – Fristen, Meilensteine. Tage außerhalb von min/max werden als nicht verfügbar angesagt und lassen sich nicht wählen. Pfeile gehen einen Tag oder eine Woche weiter, Pos1/Ende an die Enden der Woche, Bild↑/Bild↓ einen Monat (mit Umschalt ein Jahr), Enter oder Leertaste wählt; ein Tag steht in der Tab-Reihenfolge. Monatsnamen, Wochentage und den ersten Wochentag liefert die Sprache der Seite; week-start="1" legt Montag fest. Mit floating sheet ist es ein Popover, das show(anchor) unter einer Eigenschaft oder Zelle öffnet, und auf dem Telefon ein Bottom Sheet; eine Wahl schließt es. Einen schwebenden direkt unter <body> legen: Ein offener nk-dialog, nk-modal oder nk-sheet lässt ihn bedienbar, er öffnet also auch aus einem Feld im Dialog.

<nk-steps> Schritte

Ein kurzer Ablauf – ein Konto verbinden, ein Modell einrichten –, ruhig und vertikal: ein nummerierter Kreis pro Schritt, verbunden durch eine Haarlinie, erledigte Schritte mit Haken auf dem grünen Tag, der aktuelle im Akzent umrandet und mit aria-current="step" markiert. current zählt ab 1; einer hinter dem letzten markiert alle Schritte als erledigt, next() geht weiter. Das Attribut steps ist eine kommagetrennte Liste; die Property nimmt auch { label, desc }-Objekte für eine Zeile unter dem Label. Ein state in so einem Objekt – done, skipped oder open – geht der Reihenfolge vor, für einen Assistenten, der einen Schritt überspringen lässt, während ein späterer erledigt ist; ein übersprungener Schritt zeigt einen gestrichelten Ring um einen Strich. selectable macht jedes Label zum Button: Ein Klick oder Enter feuert nk-select { index, value, step } – index zählt ab 1 wie current – und macht diesen Schritt aktuell, sofern nicht abgebrochen. Ein Schritt mit href zeigt sein Label als Link, mit oder ohne selectable – um ein Kapitel in einem neuen Tab zu öffnen oder seine Adresse zu kopieren. Ein einfacher Klick und Enter feuern dasselbe nk-select; bricht man es ab, bleibt der Browser, für einen eigenen Router. Ein Mittelklick oder einer mit Cmd, Strg, Umschalt oder Alt feuert nichts und tut, was ein Link tut. horizontal setzt die Schritte in eine Zeile über einem Assistenten.

<nk-dialog> Dialog

<nk-table-view> Tabellenansicht

Rendert columns × rows als NotionKit-Tabelle. Zellen sind polymorph (text, select, multi-select, date, person, checkbox, url, number, progress) und werden vom exportierten renderPropertyCell() als Klassen-Markup gerendert – jede Zellregel beginnt mit .nk-table, ein eigenes Zellen-Element würde nie gestylt. Kopfklicks sortieren mit sortable. Eine Spalte vom Typ actions (NotionKit 1.12.0) setzt Knöpfe in jede Zeile aus column.actions – [{ action, label, icon, danger, disabled, tooltip }] –, und der Wert einer Zeile – eine Liste von Aktionsnamen – wählt, welche sie zeigt; ein Klick feuert nk-action { action, row, id, anchor }, statt die Zeile zu wählen. Ein url-Wert darf { href, label, target } sein: ein eigener Link, zu einer anderen Seite der App, mit eigenem Text. Ein Textwert darf { text, desc, color, tooltip } sein (NotionKit 1.15.0): eine leise zweite Zeile, eine von Notions neun Textfarben – orange für einen Fehler –, der ganze Text im Tooltip. Sortiert wird nach dem Wert, nicht nach dem angezeigten Text: Daten nach ihrer Zeit, Auswahlen nach der Reihenfolge ihrer Optionen, leere Zellen zuletzt; sortKey an einer Spalte sortiert nach einem anderen Feld der Zeile, ein sort im Objekt einer Zelle nach diesem Wert. Eine date-Spalte mit format – 'short', 'relative' oder den Optionen von Intl.DateTimeFormat – zeigt ISO-Daten und -Zeitpunkte formatiert in ihrer locale.

<nk-filter-bar> Filterleiste

Die wirkenden Filter als NotionKits Filter-Pills – .active mit Akzent-Tönung, je ein × zum Entfernen, am Ende eine ruhige add-Pill –, ohne Inline-Style. In slot="filters" von nk-database steht die Zeile unter der Werkzeugleiste. Das Label einer Pill feuert nk-action { action: "edit" }, die Add-Pill { action: "add" }, jeweils mit dem geklickten Button als anchor für menu.show(anchor). bar.apply(rows) behält Zeilen, bei denen jeder Filter strikt gleich ist (row[key] === value, also den Options-Wert nutzen) – oder mit op: "is-not" verschieden – und der Suchtext in einem String-Feld vorkommt (bei Personen der name); die Datenlogik bleibt deine. Eigene Filter- und Sortier-Werkzeuge und das Suchfeld sind für eine Leiste ohne Datenbank-Werkzeugleiste da. Es hält eine eigene Kopie von filters: Das übergebene Array bleibt unverändert, eine entfernte Pill wird in nk-change gemeldet.
